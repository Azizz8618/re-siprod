# Редактор языка ДРАКОН (модуль БЕМШ)

Редактор схем ДРАКОН — модуль личной библиотеки (PERSO, том 2248) рядом с
библиотекой СИПРОДа.  Модуль читает входной поток (текст программы на ДРАКОН) и
строит разметку СИПРОДа `*RED` для печати схемы на АЦПУ.

## Файлы

| файл | что это |
|---|---|
| `drakon.be` | текст модуля в формате `bemsh/*.be` (собирает `tools/siprod_asm.py`) |
| `src/drakon.be` | тот же модуль в исходном формате МАКРО-БЕМШ (собирает транслятор `БТМАЛФ`, `asmjob.py`) |
| `mklib.py` | сборка библиотеки: каталог + модули СИПРОДа + модуль редактора, запись в рабочую копию тома 2248 |
| `asmjob.py`, `build.py` | сборка модуля штатным транслятором МАКРО-БЕМШ (проверка) |
| `example.drakon` | пример входного потока |

## Сборка и запуск

```
tests/drakon/run.sh                       # собрать библиотеку и запустить
python3 drakon/mklib.py --inp drakon/example.drakon
```

Задание запускает монитор МС «Дубна» с точкой входа `DRAKON`; библиотека
пишется в **рабочую копию** тома 2248 (`drakon/out/2248`), оригинальный образ
`/usr/local/share/besm6/2248` и `siprod.bin` не изменяются.

## Вариант на автокоде МАДЛЕН (`drakon.madlen`)

Модуль в синтаксисе МАДЛЕН (мониторная система «Монитор-80», том 2348):
чтение строк через `GETSTR`, распознавание иконы по началу ключевого
слова, печать рамок иконы через `WRIKOR`, заголовок блока `*RED`/`*RG*RU`
и конец `*E`/`*END`.  Одна строка входа — одна икона.

Собирается штатным компилятором МАДЛЕН:

```
mkdir /tmp/drm-work && cd /tmp/drm-work
cp drakon/drakon.madlen drakon.masm
cp /home/azizz/Yandex.Disk/monitor80-re/tools/{asm.pl,cosy2txt,degak.py} .
cp /usr/local/share/besm6/2348 .
chmod +x asm.pl cosy2txt
BESM6_PATH=/tmp/drm-work:/usr/local/share/besm6 WORKVOL=2348 perl -CA asm.pl drakon.masm
```

Результат: листинг-дизассемблирование `drakon.dis` (объект пошёл дальше по
заданию); русский текст констант кодируется корректно (`6HЗAГOЛO`).

Открытый вопрос — путь объекта в библиотеку PERSO (том 2248):

* задание `asm.pl` заканчивает сборку директивой `*LIBRA:2` — объект
  компилятора уходит на МЛ-юнит 2 и на дисковый том **не попадает**
  (проверено дампом тома после сборки: имени модуля на томе нет); на том
  уходит только листинг (COSY в первых зонах, декодируется
  `cosy2txt | degak.py`);
* вплетание раздела команд в донорный образ формата Дубна
  (`mklib.py object_words`, донор `SCHEMA`) для этого модуля не годится:
  он объявляет **собственные** данные (`INS :LC,27`, `IKIND`) и
  собственные константы, а ссылки команд уже разрешены компилятором
  относительно его собственной раскладки.

Выясненные конвенции (для будущих шагов):

* `WRIKOR` вызывается с тремя параметрами (адрес текста, число слов,
  число знаков) — сверено с вызовами `SCHEMA` (текст 6 знаков — 1 слово;
  11 знаков — 2 слова); слово вмещает 8 знаков по 6 бит ГОСТ;
* сравнение ключевых слов в `DETECT` слово-со-словом не эквивалентно
  сравнению шести первых знаков: в слове входной строки до 8 знаков,
  а в ISO-константе из 6 знаков младшие биты — нули.  Нужна маска
  («И» по старшим знакам) или сдвиг — не сделано.

## Требования к образу модуля (выяснено опытом)

* каталог: новая запись — имя + запись (длина загрузки в словах × 8 в битах
  12..23, дата в битах 24..47); запись вставляется на место завершателя
  каталога, завершатель (пустое имя + `0о7777777777777777`) сдвигается за ней;
* модули размещаются подряд, выровненные по 32 слова; каталог занимает
  первые пять зон образа;
* образ объекта: заголовок (3 слова) + разделы `cmd | const | data | set |
  head | sym | long | debug`; длина `cmd` и `head` — в заголовке.

## Состояние

Работает: сборка модуля, сборка библиотеки, загрузка монитором, чтение
входного потока через `GETSTR` и корректный возврат в монитор.

Тонкости соглашения вызова (проверены опытом):

* выход из главной программы — как у `SCHEMA`: `УИИ М12(М16)` **до**
  `УИА <метка>(М16)`, иначе адрес возврата монитору затирается;
* вызов `GETSTR` затирает М16, поэтому при входе М16 сохраняется в магазин
  (`СЧИМ М16`), а перед выходом восстанавливается (`УИМ М16`).

Далее — разбор текста ДРАКОН, компоновка схемы и вывод разметки `*RED`.
