# Загрузчик Дубны: рецепт нового модуля (проверено опытами probe2/probe2c)

1. Формула каталога: длина загрузки = cmd + const + **bss** (ПАМ - это bss,
   НЕ data!). Ошибка длины -> «ИСПОРЧЕНА ПОДПРОГРАММА» и порча памяти.
2. Образ модуля: [заголовок 3 слова][cmd][const][set][имя][sym][long];
   w2 = cmd | bss<<15 | const<<30; set у KLAIDA пуст - обращения к общим
   блокам через МОДА релоаций не требуют.
3. Запись каталога - В НАЧАЛО (каталог отсортирован по убыванию дат).
4. sym-элемент: (0o4000+X)<<36 | C<<24 | D; позиция = номер символа модуля.
   Данные: (0o4000+база, 0, смещение) - INS24 = (1, 0, 0o30).
   Подпрограммы: (0o4000+позиция-в-каталоге, 0o6700, 3) - GETSTR = (37,6700,3)
   из ONEPLA; постоянная библиотека: FT571/FT002/FT003 = (13/10/11, 6300, 0)
   из KLAIDA.
5. Печать: FT571(&формат) -> FT002(&данные) -> FT003 (рецепт KLAIDA);
   прямая печать строки из *main - следующий этап (падение в рантайме,
   семантика параметров FT не до конца раскрыта).
6. Протокол WRIKOR: три параметра по ссылке (адрес текста, число слов,
   число знаков); сопрограмма требует живого контекста задачи SCHEMA.
