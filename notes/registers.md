# Регистры и малые смещения в модулях СИПРОДа

Разбор текстов модулей СИПРОДа (`text/*.be`, 98 модулей) — реконструированного
автокода БЕМШ.  Цель: восстановить значения регистров М1..М17 и смысл малых
смещений вида `N(Мк)`; проверить гипотезу, что малые смещения — это ссылки на
метки внутри модулей.

Инструмент: `tools/siprod_regs.py` (сводка, `--module ИМЯ`, `--json`).

```
$ python3 tools/siprod_regs.py
```

### 2.1. Соглашение вызова

Вызывающий модуль передаёт вызываемому адрес общего блока и вызывает его:

```
         МОДА   RUSIS                   ,мод.адрес := RUSIS
         СЧИМ   М16                    ,в магазин; СМ := М16
         ПВ     GETSTR(М15)            ,вызов через М15
```

Вызываемый принимает адрес блока и работает с кадром:

```
GETSTR   СТАРТ  0
         УИА    RUSISA(М16)            ,М16 := RUSISA      ; адрес блока
RUSISA   ПБ     INS24C
...
         СЧ     0(М7)                  ,СМ := 0(М7)        ; слот кадра
         СЧИМ                           ,в магазин
```

Выход из модуля — два канала (по `dis/SPAUD.asm`):

```
         СЧИМ   М1 / СЧИМ М10 / СЧИМ   ,сохранить регистры
         РЖА    '3' / РЖА '22'
         ПБ     (М12)                  ,возврат через М12
         УИМ    / УИМ М7 / УИМ М1 / УИМ М10   ,восстановить
         ПБ     (М10)                  ,возврат через М10
```

Обращение к ОС (системный запрос) — тройка `РЖА '6'` + `МОД … (М12)` +
`ПБ 0` (адрес в модифицированном адресе, см. 2.4).

### 2.2. Режим РЖ и условия переходов

`РЖА 'x'` (команда NTR) задаёт регистр режима ожидания аккумулятора; от его
разрядов зависят условия команд `ПО` и `ПЕ`:

| разряд РЖ | признак | условие `ПЕ` (переход) | условие `ПО` (переход) |
|---|---|---|---|
| 020 | G_ADD | по знаку СМ | по знаку СМ (инверсия) |
| 010 | G_MUL | по переполнению | по переполнению |
| 004 | G_LOG | СМ ≠ 0 (поразрядно) | все разряды нулевые |
| — | (по умолчанию) | СМ ≠ 0 | СМ = 0 |

В модулях СИПРОД применяются `РЖА '3'` (1385 раз) и `РЖА '22'` (1284 раза),
реже `'2'`, `'6'`, `'7'`.  Значение `'22'` = 0o22 включает признак G_ADD, то
есть после него переходы `ПО`/`ПЕ` выполняются **по знаку** СМ, а не по
необязателю.  Комментарии в текстах дают режим по умолчанию («если СМ≠0 →
метка»), поэтому при чтении модуля нужно учитывать действующий РЖ.

### 2.3. Исправленные комментарии в текстах модулей

По разбору команд (эмулятор БЭСМ-6, `~/dispak/dispak/cu.c`) уточнены
комментарии в `text/*.be`; правки внесены в генератор `tools/siprod_be.py`
(`gen_comment`), тексты пересобраны (`make be`):

| команда | было | стало |
|---|---|---|
| `СЧИМ Мк` | `стек := Мк, СМ := Мк` | `в магазин; СМ := Мк` |
| `УИМ Мк` | `Мк := СМ + стек` | `Мк := СМ; СМ := из магазина` |
| `ЗП N(Мк)` | `N := СМ` | `Мк+N := СМ` |
| `ЗП 0` | `0 := СМ` | `по адресу 0 := СМ` |
| `УИА X(Мк)` | `Мк := X` | `Мк := адрес X` |
| `УИА 0(Мк)` | `Мк := 0` | `Мк := база модуля` |
| `МОДА 0` | `мод.адрес +1: 0` | `мод.адрес := 0 (сброс модификации)` |
| `МОДА X` | `мод.адрес (+1): X` | `мод.адрес := X` |
| `МОД X(М12)` | `мод.адрес по коду: X(М12)` | `мод.адрес := код из X(М12)` |

Основания: `СЧИМ` (ITS) кладёт СМ в магазин и затем читает регистр;
`УИМ` (STI) пишет адрес из СМ в регистр и берёт вершину магазина; `УИА`
(VTM) задаёт регистр **адресом**, а не содержимым памяти; `МОДА` (UTC) и
`МОД` (WTC) заполняют регистр модифицированного адреса (R16), причём `МОД`
берёт код из слова по адресу.

Про модификатор адреса и про `МОДА 0` - в разделе 2.4.

Машинный код при этом не изменился: `make check` — 0 расхождений,
`make build` — сборка из текстов совпала с исходным образом `siprod.bin`.

### 2.4. Модификатор адреса: `МОДА`, `МОД` и `МОДА 0`

В БЭСМ-6 есть регистр модификации адреса М16 (R16) и признак, что адрес
следующей команды надо увеличить на М16.  По эмулятору
(`~/dispak/dispak/cu.c`):

```
I_UTC (МОДА):  reg[MODREG] = ADDR(адрес + регистр);  addrmod = 1;
I_WTC (МОД):   reg[MODREG] = слово по адресу (адрес + регистр).r; addrmod = 1;
адрес команды:  addr = i_addr + reg[MODREG], если addrmod (иначе i_addr);
```

Отсюда:

* `МОДА X` — М16 := адрес X; **адрес следующей команды** становится
  `своё поле + X`;
* `МОД X` — М16 := код (правая часть слова) по адресу X; адрес следующей
  команды увеличивается на этот код;
* `МОДА 0` — М16 := 0, то есть **сброс модификации**: следующая команда
  работает со своим адресом как обычно.  Это не ссылка на метку и не
  «база модуля»: загрузчик DMS не переносит литерал `0` в адресном поле
  на базу модуля (проверено трассой: после `МОДА 0` адрес следующей
  команды совпадает с её собственным полем).

Отсюда идиомы, которые видно в текстах модулей:

| последовательность | смысл |
|---|---|
| `МОДА X` + `ЗП 0` | записать СМ по адресу X (740 случаев) |
| `МОДА X` + `СЧ 0` | прочитать слово по адресу X (1116 случаев) |
| `МОДА X` + `СЛ 0`, `ВЧ 0` | прибавить/отнять слово по адресу X |
| `МОД X(М12)` + `ПБ 0` | обращение к ОС: переход по адресу из М16 (15 случаев) |
| `РЖА '6'` + `МОД X(М12)` + `ПБ 0` | то же - системный запрос монитора |

Поэтому комментарии в текстах (`tools/siprod_be.py`, `gen_comment`) теперь
учитывают модификатор: у команды, идущей за `МОДА`/`МОД`, в комментарии
называется фактический адрес («по адресу FOP := СМ»), а у `МОДА 0` —
«мод.адрес := 0 (сброс модификации)».  В шапке модуля, где есть
`МОДА`/`МОД`, добавлена строка о модификаторе адреса.

## 3. Малые смещения `N(Мк)`
### 3.1. Смещения в командах: слоты кадра, не метки модуля

Смещение при М7 — слот рабочей области (кадра задачи).  Распределение по
модулям (сколько модулей используют слот):

| слот | модулей | слот | модулей | слот | модулей |
|---|---|---|---|---|---|
| 0 | 84 | 4 | 54 | 8 | 49 |
| 1 | 76 | 5 | 44 | 9 | 47 |
| 2 | 58 | 6 | 47 | 10 | 84 |
| 3 | 56 | 7 | 42 | 11 | 33 |
| | | | | 12..30 | 31..5 |

Резкий спад после слота 10 (84 → 33 модуля) отделяет **общие** слоты
кадра (0..10, ими пользуются почти все модули) от **собственных** слотов
модуля (выше 10; их используют от 5 до 33 модулей, в сложных — SPAUD до 63,
BEGPG до 38, PAPRAP до 34).  В шапке модуля это отражено строкой

```
*   Смещения в кадре (М7): общие 0-10, свои 11-18, 23, 26-63
```

**Проверка гипотезы.** Собственные данные модуля лежат в разделе `bss` и
адресуются поимённо (`МОДА V9`, `ЗП V9`, `УИА V9`), а не через кадр.
Сопоставление множества смещений `N(М7)` с размером `bss`:

```
модулей с кадром: 97,  max(смещение) < bss: 15
```

То есть в 82 модулях из 97 кадр **не** совпадает с разделом данных: гипотеза
«малые смещения — ссылки на метки внутри модуля» для слотов кадра **не
подтверждается**.  Собственные переменные модуля видны в таблицах символов
как `V<n>` (номер слова в `bss`), и адресуются прямо.

Прочие регистры:

* М12 — кадр параметров системного вызова (`ЗПМ 16(М12)`, `МОД 12(М12)`);
* М10 — поля блока, переданного вызывающим (`СЧ 3(М10)`, `И 8(М10)`);
* М16 — ячейки модифицированного адреса (`УИА 0(М16)` и др.);
* М17 — контекст задачи (`НТЖ 0(М17)`);
* М11, М13, М14 — адреса и счётчики в буферах (RINT, RASPI).

### 3.2. Смещения в заголовках: «Смещения в X: n» — это общие блоки
В заголовках модулей есть строки вида

```
*   Смещения в INS: 24, 25, 26
*   Смещения в SCANER: 1, 2
```

Это элементы **общих блоков** (внешних символов): `INS24` = элемент 24 блока
`INS`, и в таблице символов модуля такая запись лежит с типом «общий блок +
смещение».  Сверка всех объявленных смещений с таблицами символов:

```
объявлено смещений: 814, подтверждено таблицей символов: 814
```

(например, ANATXT: симв.1 = `*INS*`+27, симв.2 = `INS24`, симв.3 = `INS25`,
симв.4 = `INS26`; `TXT1` = `*TXT*`+4, `SCANER1` = `*SCANER*`+3).

Итак, «малые смещения» двух випов:

1. в командах `N(Мк)` — слоты кадра/стека/контекста, общие для модулей;
2. в заголовках — элементы общих блоков, т.е. **ссылки на внешние символы**,
   а не на внутренние метки модуля.

В шапках модулей теперь указываются и то, и другое — назначение регистров и
используемые слоты кадра:

### 3.3. Запись чисел в операндах: что есть ссылка, а что константа

В текстах различаются три вида операндов:

| вид | пример | что это |
|---|---|---|
| имя | `УИА INS(М16)`, `МОДА RUSIS`, `СЧ V9` | **ссылка**: локальная метка модуля или внешний символ (общий блок, точка входа) |
| число в кавычках | `СЧ '4023'(М7)` | **константа** (восьмеричная): 0o4023 = 2067 |
| число без кавычек | `ЗП 12(М7)` | **константа** (десятичная): слот кадра 12 |

Числа без кавычек в МАКРО-БЕМШ десятичные, в кавычках — восьмеричные;
генератор текста (`addr_text`) выбирает запись по величине: значения меньше
0o100 (64) — десятичные, остальные — восьмеричные в кавычках.  Из-за этого
одни и те же по смыслу слоты кадра записаны по-разному: `9(М7)` (слот 9) и
`'127'(М7)` (слот 87).  В комментариях значения приведены к десятичным
(`СМ := 87(М7)`), чтобы их нельзя было прочитать как десятичные.

Всего в текстах 13889 именованных операндов (ссылки) и 4071 констант; из них
101 — со значением не меньше 0o4000 (2048): это адреса системных областей
монитора (2049…2149 — тот же диапазон, что и номера томов 2048/2053/2099),
адресуемые через тот же регистр М7.  В шапке они отделены от слотов кадра:

```
*   Смещения в кадре (М7): общие 0-10, свои 12-15, 18, 21, 24-34,
*   вне кадра 2099
```

Имени метки здесь быть не должно: это литералы, а не ссылки на метки
модуля.  Проверка: перемещаемые адреса в текстах именованы полностью (нет
заглушек вида `*0012B`), а сборка библиотеки из текстов совпадает с исходным
образом побайтово — значит, при переносе ничего не потеряно.

В шапках модулей указываются и то, и другое — назначение регистров и
используемые слоты кадра:

### 3.4. Смысл литералов в комментариях

Для констант в комментариях указывается их смысл, а не само число:

| операнд | комментарий | смысл |
|---|---|---|
| `СЧ 9(М7)` | `СМ := слот кадра 9` | слот рабочей области задачи |
| `ЗП 12(М12)` | `параметр вызова ОС 12 := СМ` | параметр системного вызова |
| `НТЖ 0(М17)` | `СМ ^= поле контекста 0` | поле ИПЗ (признак состояния) |
| `ИЛИ 3(М10)` | `СМ \|= поле блока вызывающего 3` | поле блока, переданного вызывающим |
| `СЧ '4023'(М7)` | `СМ := адрес системы 2067` | адрес служебной области монитора |
| `РЖА '22'` | `РЖ := 18 (переходы по знаку)` | режим ожидания аккумулятора |
| `ЗП 0` | `по адресу X := СМ` | адрес из модификатора (МОДА/МОД), см. 2.4 |

Значения от 0o4000 (2048) и выше — **элементы каталога задачи Монитор-80**.
Каталог размещается в памяти задачи по адресу `PC+2048`
(`monitor80-re/permanent/newsyste.asm`: `CAT:,PC,2048`), отсюда и номера
2049…2159.  Установлено:

* заголовок загрузчика в dispak: `М О Н И Т О Р-8 0 (3.7) 25.09.84 (МС "ДУБНА")` —
  задача работает под Монитором-80;
* в трассировке эмулятора видны обращения по адресам 04000…04120₈ (2048…2128) —
  ровно этот диапазон;
* в карте загрузки (`tests/siprod/loadmap-dispak.txt`) этих адресов нет: они не
  загружаются вместе с библиотекой — каталог заводит монитор при старте задачи;
* супервизор (резидент ОС с тома 2099 — в пакетном эмуляторе это просто
  хранилище резидента, номера томов к структурам отношения не имеют) обращается
  к памяти задачи через отображение 0o40000+; в его таблице (зона 0103) есть
  ссылки на 0o4000xx — на кадр задачи (смещения 0…127), но не на 0o44000+.

Известные элементы каталога (по исходникам Монитор-80):

| элемент | адрес | имя | источник |
|---|---|---|---|
| +0 | 2048 | каталог томов (RDCAT/WRCAT — признаки чтения/записи томов) | `permanent/newsyste.asm` |
| +1 | 2049 | word1 (нулевое слово для инициализации) | `permanent/newsyste.asm` |
| +2 | 2050 | каталог временной библиотеки (записи по 3 слова: имя, слово информации, …); признак готовности ввода | `writlib/writlibr.asm`, `permanent/libdrum.asm` |
| +16 | 2064 | таблица страниц (PAGE = NCL = OCL) | `permanent/newsyste.asm`, `permanent/libdrum.asm` |
| +80 | 2128 | LWW | `permanent/libdrum.asm` |
| +81 | 2129 | SAV | `permanent/libdrum.asm` |
| +83 | 2131 | SAV1 | `permanent/libdrum.asm` |
| +1536 | 3584 | конец секций (lastsect) | `permanent/newsyste.asm` |

Остальные элементы (3, 4, 5, 9…14, 17…23, 26…29, 32, 34, 51, 54, 73, 75, 86,
100, 101) в исходниках Монитор-80 отдельными именами не помечены, но по
назначению группируются так: 4-5 — флаги ввода-вывода (в модулях AIRB,
HOWSMB, SYTOBIN, SYTINT идёт атомарная проверка-установка слова-флага),
17-20 — приём и вывод текста (PAPAPR, GETSTR, FIRCAR, WHATYP, TAMPYK, TARPOZ),
51 и выше — таблицы (SCHEMA, SEGTAB, RASTXT, SPAUD).

Поэтому в комментариях стоит «каталог задачи: элемент N» (а для известных —
его имя), а не «адрес системы»: принадлежность области доказана, а имена
остальных элементов предстоит восстановить по коду Монитор-80.

Имени метки в таких операндах быть не должно: это литералы, а не ссылки на
метки модуля.  Проверено и то, что за ними не спрятана метка: в 1-й структуре
признак 4 в старших разрядах поля означает «локальная метка», а у этих
адресов (2-я структура) такого признака нет, и по соответствующим смещениям
меток в модулях нет.  Все перемещаемые адреса в текстах именованы полностью
(нет заглушек вида `*0012B`), а сборка библиотеки из текстов совпадает с
исходным образом побайтово — значит, при переносе ничего не потеряно.

Команда `СДА` (сдвиг по адресу) в комментариях не разбирается — её семантика
(сдвиг на величину, взятую из слова по адресу) не восстановлена, поэтому
комментарий к ней не ставится.

### 3.5. Сборка модулей настоящим транслятором МАКРО-БЕМШ

Тексты `text/*.be` — это дизассемблирование, а не исходники: транслятор их
не принимает.  Инструмент `tools/siprod_bemsh.py` переводит их в исходный
синтаксис МАКРО-БЕМШ (как в проекте re-dispak) и компилирует штатным
транслятором, который работает в эмуляторе диспака (`ИПМ МАКРО-БЕМШ
ВЕР.06/78`).

Задание на транслятор (как в re-dispak, `asm.pl`):

```
шифр 419999^ ... лент 43(2248-ЗП)^ ... ВВД$$$^ <исходник> КВЧ$$$^ ТРН$$$^
ЧТКОМП420070^ 1-1^ БТМАЛФ^ ЗОНМОД433900  0001^ КНЦ$$$^ _$ЕКОНЕЦ
```

Что пришлось учесть при переводе:

* в МАКРО-БЕМШ нулевое смещение не пишется: `ЗП 0` → `ЗП`, `СЧ 0(М7)` →
  `СЧ (М7)`;
* элемент общего блока указывается как `ИМЯ+СМЕЩЕНИЕ` (`ADR2` → `ADR+2`),
  отрицательное смещение - как `ИМЯ-1`;
* символ с абсолютным адресом (у СИПРОДа это отрицательные смещения -
  «слово перед общим блоком») пишется обычным числом: `N5` → `-5`;
* объявления данных идут в конце модуля, как в текстах Диспака: константы
  - `К0	КОНД	В'6400000000000000'` (слово целиком; в МАКРО-БЕМШ слово
  пишется с префиксом `В`, без него - ошибка), переменные bss -
  `V0	ПАМ	1`; в конце модуля - `ФИНИШ`.  Значения констант берутся из
  текста, то есть текст модуля самодостаточен;
* внешние символы объявляются директивой `ВНЕШ` (как в re-dispak):
  `ВЗУ	ВНЕШ	ЗАПЭКС,РАЗРЕ,АДЭК`.  Это макрос из `macros.be`; в списке
  должно быть **не больше 13 имён**, а строка - не длиннее 64 знаков,
  иначе транслятор 1978 г. её обрезает и внешние символы теряются;
* дополнительные коды ДМС `Э50`..`Э77` - тоже команды, а не метки.

Результат: **все 98 модулей компилируются без ошибок**, и скомпилированный
код **совпадает с оригиналом слово в слово** - значит, раскладка меток в
текстах правильная, а транслятор 1978 г. кодирует команды ровно так же,
как объекты DMS 1984 г.  Сборка библиотеки (`make build`) берёт раздел
команд из скомпилированного кода, а остальные разделы объектов
(таблица символов, константы) и каталог - из исходного образа: их формат
задаёт Монитор-80, а транслятор 1978 г. пишет объект в формате ДИСПАК
(запакованный заголовок, свои коды перемещений).

Побочный результат - независимая проверка раскладки меток: адреса, куда
попадают ссылки на локальные метки в скомпилированном коде, должны
совпадать с адресами самих меток.

Даты в записях каталога библиотеки менять нельзя: загрузчик
Монитор-80 их проверяет, и при изменении библиотека не грузится
(«ОТСУТСТВУЕТ SCHEMA»).  Поэтому версия собранной библиотеки пишется
рядом с образом - в файл `build/siprod.bin.version`, а номер версии
(счётчик в датах каталога) у исходной библиотеки = 52.

### 3.5. Смещения меток в модулях DMS: слова, а не команды

Ссылка на локальную метку в адресном поле команды 1-й структуры записана
как `040000 + смещение`, где смещение — **слова от начала загруженного
модуля** (восьмерично).  В слове две команды, поэтому номер команды равен
`2 * смещение`.

Раньше в текстах модулей (`text/*.be`) и в листингах (`dis/*.asm`) метки
ставились на команду с номером, равным смещению, - то есть вдвое раньше
нужного места.  Например, в модуле START:

| метка | смещение DMS | было (команда) | стало (команда) | что там на самом деле |
|---|---|---|---|---|
| `FOPA` | 0o01 | 1 | 2 | `СЧ 0(М7)` - точка возврата |
| `FOPB` | 0o05 | 5 | 10 | `СЧ '4014'(М7)` - начало цикла |
| `FOPC` | 0o22 | 18 | 36 | `УИИ М10(М7)` - эпилог модуля |

Проверка (три независимых способа):

1. **Трасса эмулятора.**  В диспаке включается трассировка команд
   (`t2` в отладчике), и для каждой ссылки на метку сравнивается адрес в
   трассе с ожидаемым `база модуля + смещение`.  По модулю SCHEMA проверено
   5773 ссылки - расхождений нет ни одного; поправка `+1` тоже не
   подтвердилась: `МОДА X` задаёт М16 ровно равным адресу X.
2. **Листинг DTRAN** (`~/Yandex.Disk/dtran/dtran`, формат DMS) печатает
   метки в своём адресном пространстве (слова): у модуля KONSTA метка со
   смещением `0002B` попадает в начало раздела констант (раздел команд там
   2 слова), а метка `0122B` - в раздел bss.  Это совпадает с моделью
   «слова», а не «команды».
3. **Таблица символов DMS.**  Записи типа «относительный адрес» (0410)
   дают смещения 430, 457, 469… у модуля SCHEMA, у которого раздел команд -
   430 слов: это начало раздела констант и раздела bss, то есть опять же
   слова.

Что из этого следует для текстов:

* локальная метка раздела команд ставится на команду `2 * смещение`;
* символы разделов констант и bss попадают в раздел «ЛОКАЛЬНЫЕ СИМВОЛЫ»
  (раньше они ошибочно попадали внутрь кода) и именуются `К<n>` -
  слово n раздела констант, `V<n>` - слово n раздела bss (нумерация
  слов, а не полуслов).  Для констант в этом разделе указано и **значение**
  слова - чтобы текст модуля был полным исходником, который собирается
  настоящим транслятором МАКРО-БЕМШ (см. 3.5);
* сборщик (`tools/siprod_asm.py`) берёт смещение метки из текста и
  делит его на два, а смещения из раздела локальных символов берёт как
  есть, - поэтому машинный код не изменился: `make check` - 0 расхождений,
  `make build` - сборка совпала с исходным образом `siprod.bin`.

Заодно уточнилось, что литерал `0` в адресном поле - это ноль, а не
«база модуля»: загрузчик DMS переносит на базу модуля только адреса с
признаком структуры (040000 - локальная метка, 074000 - внешний символ).

### 3.6. Команда `УИА` и три вида её операнда

`УИА` (VTM) задаёт регистр **адресом** (`reg[i_reg] = addr`), и адрес
этот может быть трёх видов:

| операнд | что это | сколько в модулях СИПРОД |
|---|---|---|
| метка (`040000 + N`) | локальная метка модуля, N - слова от начала модуля | 1146 |
| внешний символ (`074000 + N`) | общий блок (`lc`), его элемент (`ref`) или абсолютный адрес (`abs`) | 306 |
| литерал (`N`) | число - смещение или адрес, **не** переносится загрузчиком | 190 |

Проверено трассой:

* `УИА 6(М9)` (SYTOBIN) даёт М9 := 6 - ровно литерал, без прибавления
  базы модуля;
* `УИА 0(М1)` после `МОД V1` даёт М1 := 1 - то есть `0 + М16`, а не
  «база модуля», как считалось раньше.

Отсюда идиома `УИА 0(Мк)`: она берёт значение из модификатора адреса.
В 178 случаях из 190 она стоит сразу за `МОДА`/`МОД` (значит, регистр
получает адрес или код оттуда), в остальных - просто `0 + М16`.

Символы, на которые ссылаются команды, но у которых в таблице символов
 DMS нет имени, тоже получили имена:

* запись типа `abs` (0400) - **абсолютный адрес**; в модулях СИПРОД это
  почти всегда отрицательные смещения (-1, -2, …, -48): «слово перед
  общим блоком».  Имя - по значению: `N<n>` для отрицательных (N1 = -1)
  и `A<n>` для остальных; в шапке модуля они перечислены строкой
  «Абсолютные символы»;
* ссылка на запись 0 таблицы символов - это ссылка на **сам модуль**
  (запись 0 - раздел `head`, где имя модуля), поэтому она называется
  именем модуля со смещением: `SKZONA1024` = модуль + 1024 слов.

Раньше такие символы оставались в текстах безымянными заглушками вида
`СИМ1`; теперь заглушек не осталось (проверка: 7049 ссылок на метки
в текстах, все определены).

В шапках модулей указываются и то, и другое — назначение регистров и
используемые слоты кадра:

```
*   Смещения в INS: 24, 25, 26
*   Смещения в кадре (М7): общие 0-10, свои 11-18, 23, 26-63
*   Регистры: М1 (индекс: база модуля), М7 (указатель кадра),
*   М10 (блок вызывающего), М12 (магазин, кадр параметров ОС),
*   М15 (адрес возврата), М16 (модифицированный адрес),
*   М17 (контекст задачи)
```

Номера регистров в текстах — восьмеричные (М12 = 0o12 = 10); это важно при
сопоставлении с машинным кодом.

## 4. Что из этого нужно новому модулю (редактору ДРАКОН)

Модуль, пишущийся в том же окружении (личная библиотека тома 2248, зона
2702), должен:

* возвращаться через `ПБ (М12)` или `ПБ (М10)`, восстановив регистры
  (`УИМ М7`, `УИМ М1`, `УИМ М10`);
* вызывать модули по `ПВ X(М15)`, передавая адрес общего блока через
  `МОДА X` + `СЧИМ М16`, а вызываемый — читать его через `УИА ...(М16)`;
* читать ввод через `RINT` (внешний `SYTOBI`), печатать — протоколом
  `ПЕ <адрес>` с `РЖА '3'`/`РЖА '22'` (как в `SPAUD`, `PAPRAP`);
* свои переменные держать в разделе `bss` и адресовать поимённо; кадр
  (`N(М7)`) использовать только под общие слоты 0..10.
