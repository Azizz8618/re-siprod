# Сборка библиотеки СИПРОДа: МАКРО-БЕМШ + РВС

Заметка о том, как устроена «настоящая» сборка Мониторной системы и что из
этого уже работает в проекте.

## 1. Что это такое

* **МАКРО-БЕМШ** (ИПМ МАКРО-БЕМШ ВЕР.06/78) — транслятор.  На входе — текст
  модуля на языке БЕМШ, на выходе — **объектный модуль** в формате ДИСПАК.
* **РВС** (редактор внешних связей) — линковщик Мониторной системы.  Связывает
  отдельные объектные модули в единую программу, разрешая ссылки на внешние
  символы (подпрограммы и общие блоки) и строя **оглавление** программы.
  Бинарный код РВС лежит на томе 2148 (в конфигурации эмулятора dispak) —
  это том СВС, том 2048 в исходной системе.
* **Загрузчик** (в Монитор-80 — «МД») берёт готовую программу и грузит её
  в память.

Схема сборки (пример из `besm6.github.io/wiki/examples/bemsh`):

```
модуль.be  --МАКРО-БЕМШ-->  объектный модуль  --РВС-->  программа  --загрузчик-->  память
```

## 2. Задание транслятора (МАКРО-БЕМШ)

```
шифр 419999^ ... лент 43(2248-ЗП)^ ... ВВД$$$^ <исходник> КВЧ$$$^ ТРН$$$^
ЧТКОМП420070^ 1-1^ БТМАЛФ^ ЗОНМОД43<зона> 0001^ КНЦ$$$^ _$ЕКОНЕЦ
```

* `лент 43(2248-ЗП)` — лента зон ПЕРСО тома 2248 (`-ЗП` = «зона памяти»,
  запись разрешена).
* `ЗОНМОД43<зона> 0001` — записать объектный модуль в зону ПЕРСО.
* `1-1` — записать объектный модуль, `0-0` — только листинг.

Синтаксис модуля (как в re-dispak):

```
<модуль>	СТАРТ '<адрес>'
	Е
	М
<метки> <команды>
<данные>	КОНД	В'...'
<переменные>	ПАМ	1
<модуль>	ВНЕШ	<список внешних символов>
	ФИНИШ
```

Ограничения транслятора 1978 г. (проверено опытами):

* директива `ВНЕШ` — макрос из `macros.be`; **не больше 13 имён** в списке и
  **строка не длиннее 64 знаков**, иначе строка обрезается и внешние символы
  теряются (модуль компилируется, но с «молчащими» ссылками);
* слово-константа пишется с префиксом `В` (`КОНД В'64...'`); DMS-овское
  `КОНД '64...'` транслятор не принимает;
* `Э50`..`Э77` — дополнительные коды DMS, а не метки;
* база загрузки модуля всегда 1 (`СТАРТ` без адреса, `СТАРТ 0` и
  `СТАРТ '10000'` дают одно и то же), тогда как в текстах DMS база 0, —
  адреса меток в скомпилированном коде на единицу больше.

модули («МДЛ ПРОГ НАЗ 70000»).

## 4. ПЕРСО в эмуляторе dispak

Эмулятор хранит ПЕРСО на диске томов, нумерация зон — от «барабана»
(`dispak/extra.c`, функция `ddio`):

```c
zone = uir.i_addr & 037;      /* тракт барабана */
zone = uir.i_addr & 07777;    /* зона диска */
...
zone += (u - phdrum) * 040;   /* при «физобмене» */
...
(zone + dd->offset) & 07777   /* адрес на диске */
```

* `dd->offset` — сдвиг тома по зонам; задаётся командой монитора 0112, в
  задании — формой `лен <лента> (<том> - <окт>)`;
* в файле тома физическая зона = логическая зона + 4 (`ZONE_OFFSET` в
  `dispak/disk.c`); проверено: `ЗОНМОД 0000` → зона файла 4, `ЗОНМОД 1000` →
  зона файла 516;
* номер зоны в `ЗОНМОД` восьмеричный; при этом `ЗОНМОД 3900` и `ЗОНМОД 3100`
  дают одну и ту же зону 3100 — похоже, номер зоны нормализуется по каталогу
  зон (нужно разобраться).

## 5. Точки входа СИПРОДа

Оверлеи СИПРОДа (ADAUGB, AILIB, ASUB, RCIF, WRINT, RASPS, RASPS1, COPYBI,
RNSYMB, WRZONA) — это дополнительные точки входа внутри базовых модулей.  В
каталоге библиотеки у них нет своего объекта, а **смещение точки входа
записано в младших 12 битах записи каталога**:

| оверлей  | смещение | оверлей | смещение |
|----------|---------|---------|---------|
| ADAUGB   | 13      | WRINT   | 70      |
| AILIB    | 13      | RASPS   | 20      |
| ASUB     | 27      | WRZONA  | 16      |
| RCIF     | 48      |         |         |

В таблицах символов модулей записей вида «метка» (`lp`) нет — их надо
восстановить по этим смещениям и по карте загрузки
(`tests/siprod/loadmap-dispak.txt`), а затем объявить директивой `ВХОД`.

## 6. Что уже сделано в проекте

* `tools/siprod_bemsh.py` переводит `text/*.be` в исходник МАКРО-БЕМШ и
  компилирует **все 98 модулей** без ошибок; скомпилированный код
  **побайтово совпадает** с исходным (значит, раскладка меток в текстах
  правильная);
* собирается библиотека `build/siprod.bin`: раздел команд — из
  скомпилированного кода, раздел констант — из текста, остальные разделы
  объектов и каталог — из исходного образа (их формат задаёт Монитор-80, а
  транслятор 1978 г. пишет объект в формате ДИСПАК);
* `make record` пишет библиотеку в ПЕРСО тома 2248, `make test-perso`
  проверяет, что СИПРОД из неё работает так же, как из исходной.

Осталось (связка «ВХОД + РВС»):

1. добавить в тексты директиву `ВХОД` с метками оверлеев;
2. разобраться с ошибкой РВС «***ОШИБКА: АДРЕС 00000 < НАМ» (адрес модуля
   определяется неверно) и с нумерацией зон ПЕРСО;
3. собрать библиотеку РВС и сравнить её с исходной (оглавление, адреса,
   таблица символов) — тогда метаданные объектов тоже будут получены
   настоящим линковщиком, а не взяты из исходного образа.
