# Запись редактора в зону 2150(8) тома 2348: механизм и опыты

Как записать редактор `*RED` СИПРОД-П (РЕДÀКТ + DRАКОН) в зону 2150(8)
тома 2348 **без** библиотеки компилятора Паскаля из зоны 2570(8), и почему
прежний способ дописывал туда всю библиотеку 2570. Документ фиксирует
диагноз, проверенные опыты (08.11.2026, эмулятор dispak, Монитор-80 3.7)
и принятое решение. Исполнительный сценарий - `запись-2348.sh`.

## 1. Диагноз

Прежняя колода записи (`запись-2348.sh` до 08.11.2026):

```
user 419900 зс5^
лен 40(2348-wr)^
ЕЕВ1А3
*name
*call yesmemory
*perso:402570          ← библиотека Паскаля во временный каталог задачи
*call *pascal
<redakt.pas>
*call *pascal
<drakon.pas>
*to perso:402150       ← пишет ВЕСЬ временный каталог
*end file
```

Карта `*PERSO:LUZZZZ` читает библиотеку **во временный каталог задачи**
(PERSO.md проекта pascal-re), компилятор добавляет в тот же каталог
скомпилированные модули, а карта `*TO PERSO:LUZZZZ` пишет **весь**
временный каталог обратно на том. Поэтому в зону 2150 попадали PASCOMPL
и все модули run-time: монитор печатал «ДЛИНА LIBRARY 0o126 ЗОН» (86
зон), каталог зоны 2150 начинался с `DRАКОN`, `RЕДÀКТ` и далее
повторял каталог библиотеки 2570 (`РRО203`, `ZАР203`, `Р/31`...,
`РАSСОМРL`).

Карта `*STAND` в колоде не стояла, значит компиляция шла штатным
системным компилятором 15.0 (без `*STAND` монитор игнорирует PASCOMPL из
временного каталога и берёт предсвязанный оверлей) - то есть загрузка
`*perso:402570` была для компиляции **не нужна вовсе** и служила только
источником засорения временного каталога.

## 2. Почему не подошли «вычитание» и отбор связки

Проверены оба штатных механизма очистки временного каталога, описанных в
инструкции Паскаль-Монитора (wiki besm6.github.io, `pascal-monitor.txt`,
раздел 2.1) и в описании библиотеки (`pascal-re/library.txt`).

### 2.1. LIBSUB («вычитание» библиотеки)

Документированное применение: `*CALL LIBSUB` + карта `LUZZZZ` вычитает
содержимое perso-библиотеки из временного каталога, после чего
`*TO PERSO` дописывает в личную библиотеку только новые модули.

Опыты (запись в свободную зону 0o5000, контроль каталога `besmtool view`):

| опыт | колода | результат |
|---|---|---|
| 1 | `*perso:402570`, `*stand`, ОДНА программа, `*call libsub 402570`, `*to perso` | «ДЛИНА LIВRАRУ 003 ЗОН», в каталоге только программа - **работает** |
| 2 | две программы подряд, затем libsub | в каталоге только **последняя** программа, первая потеряна |
| 3 | две программы (compil. 15.1 через `*stand`) **без** libsub | обе программы на месте (0o65 зон с библиотекой Паскаля) |
| 4 | `*perso:402150` (целевая библиотека, как в примере инструкции), затем 402570,cont, две программы, libsub | первая скомпилированная программа потеряна |
| 5 | загруженный из perso модуль, libsub, `*to perso` | каталог пуст - вычтено всё |

Вывод: в этой реализации LIBSUB в каталоге выживает только **последний**
скомпилированный модуль; написанные раньше (и загруженные из perso)
записи вычитаются вместе с библиотекой. Для двух модулей редактора
(РЕДÀКТ и DRАКОН) механизм в одном задании неприменим; годится схема
«одна программа - одно задание - своя зона» с последующим слиянием
тремя заданиями, но есть способ проще (п. 3).

### 2.2. Отбор связки картами `*table:liblist`

В инструкции Дубны и в примере `wiki/examples/liblist.b6`:

```
*table:liblist(pasmitxt)
*liblist:670440
*to perso:41
```

Опыты:

| опыт | колода | результат |
|---|---|---|
| `*table:liblist(DRAKON)` + `*liblist:402150` + `*to personal library:405000` | одно имя | новая библиотека из одного модуля - **работает** |
| `*table:liblist(REDAKT,DRAKON)` (запятая) | два имени | карта не разобрана, отбор не действует: записано всё (0o106 зон) |
| две карты `*table:liblist(...)` подряд | по одному имени | действует только последняя (таблица перезаписывается) |
| `*table:liblist(REDAKT DRAKON)` (пробел) | два имени | отбор с одним «именем из двух слов», совпадений нет: пустая библиотека (003 зоны) |
| таблица и повторная `*to perso` | - | таблица **персистентна**: действует на все последующие записи |

Отбор работает, но синтаксис списка из нескольких имён на одной карте
не подобран, а персистентность таблицы усложняет последующее слияние.

## 3. Принятое решение

Убрать причину, а не следствие: **не загружать библиотеку 2570 в
временный каталог**. Компиляция штатным системным компилятором (карта
`*call *pascal` без `*perso` и без `*stand`) оставляет во временном
каталоге только скомпилированные модули, и `*to perso:402150` пишет
ровно их:

```
user 419900 зс5^
лен 40(2348-wr)^
ЕЕВ1А3
*name
*call yesmemory
*call *pascal
<redakt.pas>
*call *pascal
<drakon.pas>
*to perso:402150
*end file
``````
ЕКОНЕЦ
```

Монитор печатает «ДЛИНА LIВRАRУ 024 ЗОН» (2 зонных каталога + 18 зон
модулей); каталог зоны 2150 содержит RЕДÀКТ и DRАКОН и не содержит
РАSСОМРЛ.

Контроль качества записанного редактора (прогон **с тома**,
`*perso:402150` + `*perso:402570,cont` + `*call redakt`):

* все 16 эталонов оригинального СИПРОДа `tests/siprod/cases/red-*.out` -
  **совпадение побайтно**;
* схема ДРАКОН `drakon/schemes/01-vyzov-potok` через DRАКОН с тома -
  совпадение с эталоном (115 строк);
* режим `*DRK` (печать `demo/demo6-силуэт`) - совпадение с
  перегенерированным `demo/demo6-печать.txt`;
* run-time при запуске берётся из библиотеки Паскаля (2570), она
  монтируется только на чтение.

Компилятор 15.1 из PERSO (`*perso:402570` + `*stand`) для записи
редактора не используется не из-за качества кода (поведение собранного им
редактора на проверенных случаях то же, что у системного компилятора), а
потому что он требует загрузки библиотеки 2570 во временный каталог - то
есть сам создаёт проблему, которую решаем. Для сборки самого компилятора
и измерений (`замер.sh`) путь 15.1 сохранён без изменений.

Примечание об эталонах печати. По эталону оригинала red-fill
единственный лишний пробел при выравнивании ставится в предпоследний
промежуток (как записано в правиле от 07.11.2026), и текущий исходник
ему следует. Прежние эталоны demo (`redakt.out`, `demo6-печать.txt`)
были сняты с модуля, собранного до этого исправления, и содержат пробел
в последнем промежутке - поэтому свежесобранный редактор расходится с
ними на один пробел (demo1, строка 8) и на пустую строку шапки страницы
в печати *DRK, оставаясь верным оригиналу СИПРОДа на всех 16 эталонах
red-*. Эталоны перегенерированы с тома по текущему исходнику
(`redakt.out`, `demo/demo5-печать.txt`, `demo/demo6-печать.txt`,
`схемы/печать-каталог.txt`).

## 4. Состояние тома

Было (том 2348 до работ): зона 0o2150 - библиотека связки 0o126 зон
(компилятор + run-time + редактор), данные до 0o2255.

Стало: зона 0o2150 - библиотека редактора 0o24 зон (0o2150..0o2173:
2 зонных каталога, РЕДÀКТ, DRАКОН); хвост прежней записи 0o2174..0o2255
стёрт свободным паттерном (4 нулевых байта + сигнатура `80 c7 f1 05` в
шапке зоны); остальные зоны тома, включая библиотеку Паскаля 0o2570 и
рабочие зоны re-siprod (0o2000, 0o2100), не изменены.
