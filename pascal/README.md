# Редактор `*RED` СИПРОД-П и транслятор ДРАКОН на Паскале-Мониторе

Дополнение к re-siprod: реализация режима `*RED` текстовой системы
СИПРОД (БЭСМ-6) и транслятора схем языка ДРАКОН на языке Паскаль-Монитор
(МС «Дубна»), отладка на пакетном эмуляторе
[dispak](https://github.com/Azizz8618/dispak) с восстановленным
компилятором [pascal-re](https://github.com/Azizz8618/pascal-re)
(PASCOMPL 15.1, PERSO-библиотека тома 2348).

```
  текст ДРАКОН ──> drakon.pas ──> разметка *RED ──> redakt.pas ──> АЦПУ-128
                     (схема)        (*RG*RU,          (редактор)     (печать)
                                     */*D-карты)

  текст ДРАКОН ──> redakt.pas (*DRK ... *E) ─────────────────> АЦПУ-128
                     (схема)       (режим встроен в редактор)
```

Папка самодостаточна: исходники, готовая колода, сценарии прогона,
регресса и записи на диск, демо-примеры, справочник команд.  Эталоны
берутся из этого же репозитория (`../tests/siprod/cases`,
`../drakon/schemes`), описание печатных средств редактора - в
`../SIPROD.md`, справочник по ДРАКОН - в `../DRAKON.md`.

## Запуск

Нужен dispak (собранный из ../.. или https://github.com/Azizz8618/dispak)
и образ тома 2348 с PERSO-библиотекой компилятора Паскаль
(`*perso:402570`, зона 2570(8); том монтируется только на чтение):

```
DISPAK=путь/к/dispak BESM6_PATH="каталог/с/томами:..." \
    ./прогнать.sh redakt.pas demo/demo1-текст.txt

# схема ДРАКОН -> разметка -> печать редактором:
./прогнать.sh drakon.pas demo/demo5-дракон.txt > разметка.txt
./прогнать.sh redakt.pas разметка.txt

# схема ДРАКОН -> печать редактором (*DRK, режим встроен):
{ echo '*DRK'; cat demo/demo5-дракон.txt; echo '*E'; } | ./прогнать.sh redakt.pas
```

Готовой колодой (компиляция и выполнение одним пакетом, без сценариев):

```
DISPAK=путь/к/dispak BESM6_PATH="..." dispak redakt.b6
```

## Тестовое задание: паспорт и диспетчерский конец

`тест-задание.b6` - полное задание Диспака: паспорт (`user ... зс5^`,
`лен 40(2348)^`, конец паспорта `ЕЕВ1А3`), вызов редактора с тома
(`*perso:402150`, `*call redakt`) и печать схемы `demo/demo6-силуэт`
(силуэт: три ветки с переходами по АДРЕС - «Паспорт», «Вызов редактора»,
«Конец задания»), в конце - диспетчерская карта `ЕКОНЕЦ`.  Рисунок
схемы занимает две страницы и пересекает границу страниц: рамки фигур
на ней не должны рваться.  Пересобрать колоду:

```
./прогнать-с-тома.sh drakon demo/demo6-силуэт.drakon > demo/demo6-разметка.txt
./собрать-тест.sh
DISPAK=... BESM6_PATH="..." dispak тест-задание.b6
```

Тот же силуэт печатается без карт разметки - режим ДРАКОН встроен
в редактор как блок `*DRK` верхнего уровня (наравне с `*RED`, аналог
своего режима в таблице SCHEMA оригинала):

```
*DRK
<demo/demo6-силуэт.drakon>
*E
```

Блок сам включает рамку и широкий формат; выдача побайтно равна
`demo/demo6-печать.txt` (проверяется секцией «*DRK = разметка» в
`регресс.sh` и прогоном с тома).

Выдача задания - печать схемы на АЦПУ (`demo/demo6-печать.txt`).

## Запись на том 2348, зона 2150(8)

`запись-2348.sh` записывает библиотеку связки на том 2348 тем же
«мониторным путём», каким tools/catchup2348_monitor.sh догоняет том
СИПРОДом: задача Монитора-80 монтирует том с правом записи
(`лен 40(2348-wr)^`), загружает PERSO-библиотеку компилятора
(`*perso:402570^`), транслирует оба исходника (`*call *pascal`) и
записывает временный каталог задачи на том (`*to perso:402150^`).
Монитор печатает `ДЛИНА LIBRARY 100 ЗОН` (октально, с каталогом;
РЕДАКТ вырос - в него встроен режим ДРАКОН `*DRK`):
библиотека укладывается в свободный промежуток `0o2150..0o2300`
(лимит `0o130` зон, лимит проверяется сценарием).

После записи редактор и транслятор запускаются с тома без компиляции:

```
лен 40(2348)^
*perso:402150
*call redakt
<текст режима *RED>
```

или сценарием: `./прогнать-с-тома.sh redakt demo/demo1-текст.txt`
(для разметки ДРАКОН: `./прогнать-с-тома.sh drakon demo/demo5-дракон.txt`).

Сценарий делает резерв тома, перед записью проверяет, что зона свободна
или занята нашей же библиотекой (перезапись идемпотентна), после записи -
что каталог зоны содержит `РАSСОМРL`, `RЕДАКТ`, `DRАКОН`, что занятые
зоны вне области записи не изменились и что редактор, загруженный
с тома, печатает на `demo/demo1-текст.txt` побайтно ту же выдачу, что
`redakt.out`.  Первый прогон делайте на рабочей копии тома (том должен
быть первым в `BESM6_PATH`); боевой том подключайте явно и только после
успешного прогона.

Ручная запись без сценария - колода из трёх карт и тел исходников:

```
user 419900 зс5^
лен 40(2348-wr)^
ЕЕВ1А3
*name
*call yesmemory
*perso:402570
*call *pascal
<текст redakt.pas, ГОСТ-10859: верхний регистр, Ё->Е>
*call *pascal
<текст drakon.pas, так же>
*to perso:402150
*end file
``````
ЕКОНЕЦ
```

## Редактор: реализованные средства режима *RED

* модель страницы АЦПУ-128: две страницы по 64 позиции на листе
  (67 строк: прогон, номер, 60 строк текста, поля), формат А (84
  позиции), широкий формат (одна страница во всю ширину листа);
* прогон страницы (ГОСТ 0201) перед строками листа - прямым вызовом
  экстракода 64 (системные процедуры `besm` и `REF`, тест
  `э64-тест.pas`): стандартный вывод Паскаля 6-битный и байт 0201
  через него недоступен; в выдаче задачи каждый лист начинается
  строкой с прогоном, как в эталонах оригинала;
* заполнение по словам с выравниванием по обоим краям, перенос длинного
  слова, отступ абзаца 3;
* команды: `*nS *n/ *nP *E *D *nH *nG *nCc *Knc *nFc *nRFc *n(текст)`
  `*nWтекст) *T *MD *nRL *nRC *OLR *RT *RU *ORU *nMCS *nMCP *nN *NN`
  `*RG *nSTA *nSTO *nSTP *nSTG *STN *MF *///`, число без команды
  (листинг);
* таблицы `*ST` (колонки) и `*SL` (с линейками) с ячейками `k)`,
  продолжением ячейки и отменой линеек `*NL *NR *NU *ND`;
* макроопределения `*nM=тело$` (тело через несколько карт) и вставки
  `*nM` с вложенным раскрытием (без рекурсии: стек уровней + докрутка
  в главном цикле);
* штамп ЕСПД (строка под номером страницы) и подвал, в т.ч. «только на
  первой странице»; первая карта блока разбирается как FIRCAR
  (команды заголовка действуют немедленно);
* номера страниц от `*nN`, нумерация с продолжением через листы,
  смена формата со следующей страницы;
* ошибки 10 20 30 40 61 62 64 66 80 91 100 в формате оригинала
  (`ERROR NR. n`, `ОБРАЗ ПЕРФОКАРТЫ:`).

## ДРАКОН

Перенос эталонного генератора разметки (`../tools/drakon_markup.py`) на
Паскаль-Монитор: разбор текста схемы по отступам, дерево узлов, перенос
длинных подписей, компоновка по шампуру с правыми плечами развилок
(`ЕСЛИ`/`ЦИКЛ`/`ВЫБОР` + `ТО`/`ИНАЧЕ`/`ВАРИАНТ`), рисование полного
комплекта икон по рис. 4 книги Паронджанова (И1-И25) с соединительными
линиями, возвратами плеч, слиянием маршрутов и автоматической петлёй
цикла ДЛЯ, выдача разметки `*RED` (`*RG*RU` + `*/*D`-карты) для печати
схемой редактора.

Входной язык - 28 ключевых слов с двоеточием или без:
`ЗАГОЛОВОК ВЕТКА ДЕЙСТВИЕ КОММЕНТАРИЙ ЕСЛИ ЦИКЛ ВЫБОР ВАРИАНТ АДРЕС
КОНЕЦ ТО ИНАЧЕ ПОЛКА ПАРАМ ДЛЯ КДЛ ВЫВОД ВВОД ПАУЗА ПЕРИОД ПУСК СИНХРО
ПАРАЛ ПКОМ ЛКОМ ПЕТЛЯ ГРЕБЕНКА ВСТАВКА`; строки с `*` - комментарии.
Эталонные схемы - `../drakon/schemes/*.drakon`; испытание всех икон -
`схемы/18-иконы-примитив.drakon` и `схемы/19-иконы-силуэт.drakon`.

**Формы икон по книге Паронджанова (06.11.2026)**: все иконы переделаны
по рис. 4 (полуовалы заголовка/конца, щит имени ветки, шестиугольник
вопроса с валентной точкой на середине высоты, параллелограмм выбора,
клин варианта, домик адреса, двойные стенки вставки, полка, формальные
параметры, цикл ДЛЯ, вывод/ввод, пауза/период/пуск/синхронизатор,
параллельный процесс, комментарий в двойной рамке, скобочные
комментарии, петля цикла и гребёнка силуэта).  Литеры `\` на бумаге
АЦПУ-128 нет: скос вправо-вниз рисуется `(`, сходы - скобочной парой
`( ... )`; ширины всех икон нечётные - вершины и острия стоят точно на
оси шампура.  Добавлена автоматическая петля цикла ДЛЯ (возврат от КДЛ
остриём в вертикаль под ДЛЯ); боковой выход вопроса - с середины
высоты правой стены.  Эталоны 01-06, 07-19, demo6 и печать-каталог
перегенерированы; маршруты разметка и `*DRK` совпадают побайтно.

**Встроенный режим `*DRK`** — тот же транслятор, собранный в один
образ с редактором: блок верхнего уровня наравне с `*RED` (аналог
«своего режима в schema» оригинального СИПРОДа):

```
*DRK
<исходник схемы>
*E
*END
```

Блок сам включает рамку и широкий формат; строки рисунка идут через
механизм строк редактора (рамки на границах страниц, номера и штампы
ведёт редактор); выдача побайтно равна печати через разметку.
Ёмкость: 72 узла, 208 строк рисунка (отдельный `drakon.pas` —
120/240, для схем побольше).

## Найденные и исправленные ошибки (06.11.2026)

Проверка печати фигур ДРАКОН на АЦПУ (`схемы/печать-каталог.txt`)
выявила три ошибки - все исправлены:

1. **Редактор `redakt.pas`: строка, зафиксированная точно на границе
   страниц, печаталась пустой** - при переходе на следующую страницу
   рамки фигур обрывались (в `печать-каталог.txt` на границе страниц
   4/5 иконы теряли верхнюю/нижнюю сторону и вертикали).  Причина:
   `commitrow` вызывает `pageend`, а тот через `pagestart -> newsheet`
   стирает `cur`; параметр `r` в `commitrow` - тот же `cur` (var-пара-
   метр-алиас), и запись строки на новый лист читала уже пустую строку.
   Исправление: копия строки `sv` сохраняется перед `pageend` и
   восстанавливается после него.

2. **Транслятор `drakon.pas`: терялось слово длинной подписи иконы**
   (например, «Библиотека perso 402150» рисовалось как
   «БИБЛИОТЕКА PERSO» без «402150»).  Причина: компилятор 15.1 не
   гарантирует короткое замыкание `or` - в `wraptl` при `cur = 0`
   читалось и писалось `wln[0]`/`wtx[0]` вне массива, порча соседних
   переменных зависела от остатков памяти.  Исправление: условие
   переписано вложенными `if` без обращения к `wln[cur]` при `cur = 0`.

3. **`прогнать-с-тома.sh`: awk-фильтр выдачи съедал строки с «402150»**
   (и следующую `*`-строку) - признак `/402150/` для пропуска эха карты
   `*perso:402150` совпадал и с картами разметки, содержащими это число.

## Отличия от оригинала

* прогон страницы реализован (07.11.2026) прямым вызовом экстракода
  64 из Паскаля (`besm`+`REF`): выдача каждого листа начинается
  строкой с прогоном, как у оригинала; остался нюанс - у оригинала
  перед прогоном бывает вторая прогонная строка, порт выдаёт одну;
* распределение лишних пробелов при выравнивании: при одном лишнем
  пробеле он ставится не в тот промежуток, что в оригинале («к
  последним промежуткам» снято с 3 эталонов, расходится в 2 из 16);
* рамка вокруг листа рисуется и у неиспользованной половины; на
  последнем листе с одной пустой половиной номер/штамп сдвинуты на
  строку (случай red-header/red-pages);
* подвал `*STG` центрируется по ширине страницы без учёта полей
  `*MCS`;
* знак `?` печатается градусом `°` (в ГОСТ-10859 вопроса нет - так же
  ведёт себя библиотека оригинала);
* рекурсивные ссылки на результат функции, `exit` внутри циклов и
  рекурсия процедур зацикливали/переполняли компилятор 15.1 - в тексте
  использованы только конструкции, проверенные на его собственном
  исходнике; раскрытие макро сделано итеративным.
