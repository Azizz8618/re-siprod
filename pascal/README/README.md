# Редактор `*RED` СИПРОД-П и транслятор ДРАКОН на Паскале-Мониторе

Дополнение к re-siprod: реализация режима `*RED` текстовой системы
СИПРОД (БЭСМ-6) и транслятора схем языка ДРАКОН на языке Паскаль-Монитор
(МС «Дубна»), отладка на пакетном эмуляторе
[dispak](https://github.com/Azizz8618/dispak) с восстановленным
компилятором [pascal-re](https://github.com/Azizz8618/pascal-re)
(PASCOMPL 15.1, PERSO-библиотека тома 2348).

```
  текст ДРАКОН ──> ../source/drakon.pas ──> разметка *RED ──> ../source/redakt.pas ──> АЦПУ-128
                     (схема)        (*RG*RU,          (редактор)     (печать)
                                     */*D-карты)

  текст ДРАКОН ──> ../source/redakt.pas (*DRK ... *E) ─────────────────> АЦПУ-128
                     (схема)       (режим встроен в редактор)
```

Папка самодостаточна: исходники, готовая колода, сценарии прогона,
регресса и записи на диск, демо-примеры, справочник команд.  Эталоны
берутся из этого же репозитория (`../../tests/siprod/cases`,
`../../drakon/schemes`), описание печатных средств редактора - в
`../../SIPROD.md`, справочник по ДРАКОН - в `../../DRAKON.md`.

## Запуск

Нужен dispak (собранный из ../../.. или https://github.com/Azizz8618/dispak)
и образ тома 2348 с PERSO-библиотекой компилятора Паскаль
(`*perso:402570`, зона 2570(8); том монтируется только на чтение):

```
DISPAK=путь/к/dispak BESM6_PATH="каталог/с/томами:..." \
    ../scripts/прогнать.sh ../source/redakt.pas ../demo/demo1-текст.txt

# схема ДРАКОН -> разметка -> печать редактором:
../scripts/прогнать.sh ../source/drakon.pas ../demo/demo5-дракон.txt > разметка.txt
../scripts/прогнать.sh ../source/redakt.pas разметка.txt

# схема ДРАКОН -> печать редактором (*DRK, режим встроен):
{ echo '*DRK'; cat ../demo/demo5-дракон.txt; echo '*E'; } | ../scripts/прогнать.sh ../source/redakt.pas
```

Готовой колодой (компиляция и выполнение одним пакетом, без сценариев):

```
DISPAK=путь/к/dispak BESM6_PATH="..." dispak ../redakt.b6
```

## Тестовое задание: паспорт и диспетчерский конец

`../тест-задание.b6` - полное задание Диспака: паспорт (`user ... зс5^`,
`лен 40(2348)^`, конец паспорта `ЕЕВ1А3`), вызов редактора с тома
(`*perso:402150`, `*call redakt`) и печать схемы `../demo/demo6-силуэт`
(силуэт: три ветки с переходами по АДРЕС - «Паспорт», «Вызов редактора»,
«Конец задания»), в конце - диспетчерская карта `ЕКОНЕЦ`.  Рисунок
схемы занимает две страницы и пересекает границу страниц: рамки фигур
на ней не должны рваться.  Пересобрать колоду:

```
../scripts/прогнать-с-тома.sh drakon ../demo/demo6-силуэт.drakon > ../demo/demo6-разметка.txt
../scripts/собрать-тест.sh
DISPAK=... BESM6_PATH="..." dispak ../тест-задание.b6
```

Внимание: этот прогон требует модуля DRАКОН на томе 2348 - по умолчанию
(../scripts/запись-2348.sh, TOLKO_REDAKT=1) он там не записывается: разметку
строят через `../scripts/прогнать.sh ../source/drakon.pas` (компиляция из исходника) либо
печатание возвращают записью с TOLKO_REDAKT=.

Тот же силуэт печатается без карт разметки - режим ДРАКОН встроен
в редактор как блок `*DRK` верхнего уровня (наравне с `*RED`, аналог
своего режима в таблице SCHEMA оригинала):

```
*DRK
<../demo/demo6-силуэт.drakon>
*E
```

Блок сам включает рамку и широкий формат; выдача побайтно равна
`../demo/demo6-печать.txt` (проверяется секцией «*DRK = разметка» в
`../scripts/регресс.sh` и прогоном с тома).

Выдача задания - печать схемы на АЦПУ (`../demo/demo6-печать.txt`).

## Демо 7: шаблон задания «Пост в телеграм»

`../demo/demo7-телеграм.txt` - колода `*RED`, печатающая бланк поста
для канала телеграм; печать бланка - `../demo/demo7-печать.txt`
(снята прогоном с тома; скомпилированный редактор даёт ту же выдачу).
Страница узкая: широкий формат `*RU` (одна страница на листе) без
рамки, номера страниц сняты (`*NN` - иначе номер печатается в колонках
42-47 и ломает узкий лист), поле текста `*0MCS1 30` - колонки 6-35.
Строка печати не шире 35 позиций, строки поста - 30: бланк переносится
в канал с телефона без переноса строк.  Поля формы - подчёркивания
`*nF_`: при подготовке очередного поста замените их текстом и подайте
колоду в Диспак как обычную задачу пользователя.

```
../scripts/прогнать-с-тома.sh redakt ../demo/demo7-телеграм.txt
```

## Запись на том 2348, зона 2150(8)

`../scripts/запись-2348.sh` записывает на том 2348 редактор РЕДÀКТ (по умолчанию -
только он: транслятор схем ДРАКОН встроен в редактор как режим `*DRK`;
отдельный `../source/drakon.pas` на том не записывается; вернуть DRАКОН -
пустой переменной `TOLKO_REDAKT=`) - без библиотеки компилятора
Паскаля, причём трансляция идёт именно компилятором PASCOMPL 15.1 из
зоны 2570(8) (баннер системного компилятора «15.0 (15.02.82)» в журнале
записи запрещён - сценарий это проверяет).

Схема двухфазная.  Карта `*perso` читает библиотеку ЦЕЛИКОМ во временный
каталог задачи, а `*to perso` пишет весь каталог обратно: одна колода
«`*perso:402570` + трансляции + `*to perso:402150`» таскала в зону 2150
все ~100 зон библиотеки 2570 (компилятор и весь run-time).  Вычистить
временный каталог штатно нечем: приказ Y программы pashelp убирает
только имена «P/», «PAS» и TIME; карта `*EXCLUDE` отвязывает модули от
памяти задачи, каталог на диске не трогает; LIBSUB в этой реализации
оставляет в каталоге только последний скомпилированный модуль.  Опыты
и активный тест LIBDELET - в [ЗАПИСЬ-2150.md](ЗАПИСЬ-2150.md).  Поэтому
каждая фаза - отдельное задание Монитора-80:

```
фаза 1а: *perso:402570, *stand, *call *pascal <../source/redakt.pas>,
         *call libsub + карта 402570, *to perso:405000
         -> черновик А: только РЕДÀКТ (0o16 зон);
фаза 1б: то же для ../source/drakon.pas -> черновик Б: только DRАКОН (0o11);
         не выполняется по умолчанию (TOLKO_REDAKT=1);
фаза 2:  *perso:405000 + *perso:405100,cont (слияние черновиков
         во временном каталоге) + *to perso:402150 - каталог и
         размещение модулей строит сам монитор (0o24 зон).
```

Черновые зоны (0o5000 и 0o5100; переназначаются переменными окружения
CHERNOVIK_A/CHERNOVIK_B) и хвост прежней записи за новой длиной стирает
сам сценарий - свободным паттерном.  По умолчанию фаза 1б не строится
(TOLKO_REDAKT=1): на томе остаётся только ДЛИНА LIBRARY 016 (редактор);
DRАКОН добавляется опять пустой переменной TOLKO_REDAKT=.

После записи редактор запускается с тома без компиляции, вместе
с run-time из библиотеки Паскаля (том монтируется только на
чтение):

```
лен 40(2348)^
*perso:402150
*perso:402570,cont
*call redakt
<текст режима *RED>
```

или сценарием: `../scripts/прогнать-с-тома.sh redakt ../demo/demo1-текст.txt`
(для разметки ДРАКОН: `../scripts/прогнать-с-тома.sh drakon ../demo/demo5-дракон.txt`).

Сценарий делает резерв тома, перед записью проверяет, что в зоне 0o2570
есть РАSСОМРL, зона 0o2150 свободна или занята нашей же библиотекой
(перезапись идемпотентна), черновые зоны свободны; после записи - что
«ДЛИНА LIBRARY» каждого задания не выше 0o30 зон, что каталог зоны
содержит RЕДÀКТ и DRАКОН и НЕ содержит ни РАSСОМРL, ни модулей «P/»
(вся соль исправления), что хвосты стёрты, что занятые зоны вне области
записи не изменились и что редактор, загруженный с тома вместе с
run-time, печатает на `../demo/demo1-текст.txt` побайтно ту же выдачу, что
`../redakt.out`.  Первый прогон делайте на рабочей копии тома (том и
системные тома 2048/2053/2099 должны лежать в `BESM6_PATH`); боевой том
подключайте явно и только после успешного прогона.

Образ редактора занимает раздел задачи почти целиком (добавление
128 слов статики уже вызывало «МАЛО ПАМЯТИ»): план выноса
нерезидентных частей и экономии ОЗУ —
[ПЛАН-ОЗУ.md](ПЛАН-ОЗУ.md).

Ручная запись без сценария - три колоды, по заданию на фазу.
Фаза 1а (фаза 1б - то же с ../source/drakon.pas и своей черновой зоной):

```
user 419900 зс5^
лен 40(2348-wr)^
ЕЕВ1А3
*name
*call yesmemory
*perso:402570
*stand
*call *pascal
<текст ../source/redakt.pas, ГОСТ-10859: верхний регистр, Ё->Е>
*call libsub
402570
*to perso:405000
*end file
``````
ЕКОНЕЦ
```

Фаза 2 (слияние черновиков и запись связки):

```
user 419900 зс5^
лен 40(2348-wr)^
ЕЕВ1А3
*name
*call yesmemory
*perso:405000
*perso:405100,cont
*to perso:402150
*end file
``````
ЕКОНЕЦ
```

## Редактор: реализованные средства режима *RED

* модель страницы АЦПУ-128: две страницы по 64 позиции на листе
  (67 строк: прогон, номер, 60 строк текста, поля), формат А (84
  позиции), широкий формат (одна страница во всю ширину листа);
* прогон страницы (ГОСТ 0201) перед строками листа - прямым вызовом
  экстракода 64 (системные процедуры `besm` и `REF`, тест
  `../../tests/pas/э64-тест.pas`): стандартный вывод Паскаля 6-битный и байт 0201
  через него недоступен; в выдаче задачи каждый лист начинается
  строкой с прогоном, как в эталонах оригинала;
* заполнение по словам с выравниванием по обоим краям, перенос длинного
  слова, отступ абзаца 3;
* команды: `*nS *n/ *nP *E *D *nH *nG *nCc *Knc *nFc *nRFc *n(текст)`
  `*nWтекст) *T *MD *nRL *nRC *OLR *RT *RU *ORU *nMCS *nMCP *nN *NN`
  `*RG *nSTA *nSTO *nSTP *nSTG *STN *MF *///`, число без команды
  (листинг);
* таблицы `*ST` (колонки) и `*SL` (с линейками) с ячейками `k)`,
  продолжением ячейки и отменой линеек `*NL *NR *NU *ND`;
* макроопределения `*nM=тело$` (тело через несколько карт) и вставки
  `*nM` с вложенным раскрытием (без рекурсии: стек уровней + докрутка
  в главном цикле);
* штамп ЕСПД (строка под номером страницы) и подвал, в т.ч. «только на
  первой странице»; первая карта блока разбирается как FIRCAR
  (команды заголовка действуют немедленно);
* номера страниц от `*nN`, нумерация с продолжением через листы,
  смена формата со следующей страницы;
* ошибки 10 20 30 40 61 62 64 66 80 91 100 в формате оригинала
  (`ERROR NR. n`, `ОБРАЗ ПЕРФОКАРТЫ:`).

## ДРАКОН

Перенос эталонного генератора разметки (`../../tools/drakon_markup.py`) на
Паскаль-Монитор: разбор текста схемы по отступам, дерево узлов, перенос
длинных подписей, компоновка по шампуру с правыми плечами развилок
(`ЕСЛИ`/`ЦИКЛ`/`ВЫБОР` + `ТО`/`ИНАЧЕ`/`ВАРИАНТ`), рисование полного
комплекта икон по рис. 4 книги Паронджанова (И1-И25) с соединительными
линиями, возвратами плеч, слиянием маршрутов и автоматической петлёй
цикла ДЛЯ, выдача разметки `*RED` (`*RG*RU` + `*/*D`-карты) для печати
схемой редактора.

Входной язык - 28 ключевых слов с двоеточием или без:
`ЗАГОЛОВОК ВЕТКА ДЕЙСТВИЕ КОММЕНТАРИЙ ЕСЛИ ЦИКЛ ВЫБОР ВАРИАНТ АДРЕС
КОНЕЦ ТО ИНАЧЕ ПОЛКА ПАРАМ ДЛЯ КДЛ ВЫВОД ВВОД ПАУЗА ПЕРИОД ПУСК СИНХРО
ПАРАЛ ПКОМ ЛКОМ ПЕТЛЯ ГРЕБЕНКА ВСТАВКА`; строки с `*` - комментарии.
Эталонные схемы - `../../drakon/schemes/*.drakon`; испытание всех икон -
`../схемы/18-иконы-примитив.drakon` и `../схемы/19-иконы-силуэт.drakon`.

**Формы икон по книге Паронджанова (06.11.2026)**: все иконы переделаны
по рис. 4 (полуовалы заголовка/конца, щит имени ветки, шестиугольник
вопроса с валентной точкой на середине высоты, параллелограмм выбора,
клин варианта, домик адреса, двойные стенки вставки, полка, формальные
параметры, цикл ДЛЯ, вывод/ввод, пауза/период/пуск/синхронизатор,
параллельный процесс, комментарий в двойной рамке, скобочные
комментарии, петля цикла и гребёнка силуэта).  Литеры `\` на бумаге
АЦПУ-128 нет: скос вправо-вниз рисуется `(`, сходы - скобочной парой
`( ... )`; ширины всех икон нечётные - вершины и острия стоят точно на
оси шампура.  Добавлена автоматическая петля цикла ДЛЯ (возврат от КДЛ
остриём в вертикаль под ДЛЯ); боковой выход вопроса - с середины
высоты правой стены.  Эталоны 01-06, 07-19, demo6 и печать-каталог
перегенерированы; маршруты разметка и `*DRK` совпадают побайтно.

**Скобки вместо слэшей, равные поля подписей, целые иконы на границе

## Найденные и исправленные ошибки (06.11.2026)

Проверка печати фигур ДРАКОН на АЦПУ (`../схемы/печать-каталог.txt`)
выявила три ошибки - все исправлены:

1. **Редактор `../source/redakt.pas`: строка, зафиксированная точно на границе
   страниц, печаталась пустой** - при переходе на следующую страницу
   рамки фигур обрывались (в `печать-каталог.txt` на границе страниц
   4/5 иконы теряли верхнюю/нижнюю сторону и вертикали).  Причина:
   `commitrow` вызывает `pageend`, а тот через `pagestart -> newsheet`
   стирает `cur`; параметр `r` в `commitrow` - тот же `cur` (var-пара-
   метр-алиас), и запись строки на новый лист читала уже пустую строку.
   Исправление: копия строки `sv` сохраняется перед `pageend` и
   восстанавливается после него.

2. **Транслятор `../source/drakon.pas`: терялось слово длинной подписи иконы**
   (например, «Библиотека perso 402150» рисовалось как
   «БИБЛИОТЕКА PERSO» без «402150»).  Причина: компилятор 15.1 не
   гарантирует короткое замыкание `or` - в `wraptl` при `cur = 0`
   читалось и писалось `wln[0]`/`wtx[0]` вне массива, порча соседних
   переменных зависела от остатков памяти.  Исправление: условие
   переписано вложенными `if` без обращения к `wln[cur]` при `cur = 0`.

3. **`../scripts/прогнать-с-тома.sh`: awk-фильтр выдачи съедал строки с «402150»**
   (и следующую `*`-строку) - признак `/402150/` для пропуска эха карты
   `*perso:402150` совпадал и с картами разметки, содержащими это число.
   Исправление: пропуск только до начала выдачи (`f==0 && /402150/`).

  перекрывает эталон оригинала - будущие оправданные отличия
  фиксируются тем же способом;
* разобрано (08.11.2026): разбивка листа в формате А (штамп, номер и
  первая строка текста - как в оригинале, red-header) и число строк

* `*0RU` на первой карте блока (разбор FIRCAR): оригинал дописывает
  текущий лист и начинает широкий формат со следующей страницы, причём
  строка текста остаётся прежней; порт делает то же, но текст на
  первой широкой странице начинается на позицию раньше (на 1 знак).
* рекурсивные ссылки на результат функции, `exit` внутри циклов и
  рекурсия процедур зацикливали/переполняли компилятор 15.1 - в тексте

* позиционный режим (`*nG`, `*nCc`, `*nFc`, `*D`) при заполнении
  строки (128-я позиция) переходит на следующую строку (12.11.2026);

  поведение за 128-й позицией не определено (строка листа - 128
  позиций, эталоны этот случай не задевают).  Мотивировка: задание с

  выполняет команды `*C`, `*F`, `*D` в середине карты - команды

  каких-либо следов в печати; теперь текст продолжается со следующей

  `*H*` (СИПРОД.md 4.3).  Для литеры `*` в тексте документа - всегда
  `*H*`.

## Исправления 08.11.2026 (сверка с оригиналом СИПРОДа)

Последние два расхождения редактора (`red-header` - формат А, `red-wide` -
широкий формат) устранены; все 16 эталонов `red-*` совпадают побайтно.
Проверено на живом оригинале (`tests/siprod/run.sh`):

1. **Штамп `*STP`** рисуется на листе над текстом (строка 3 обычного и
   широкого формата, строка 4 формата А; на последней странице формата
   А - строка 6), а не занимает первую строку текста; текст при этом
   не сдвигается.  Порт печатает штамп и на той странице, где он задан.
2. **Подвал `*STG`** центрируется по полю страницы (`defl + (defw -
   длина) div 2`), а не по ширине листа; в обычном и широком формате он
   стоит над нижним краем листа, в формате А - на две строки выше.
3. **`*0STO`** (обычный формат) не прерывает текущую страницу: формат
   применяется со следующей страницы (у `*0STA` и `*0RU` - прерывает).
4. **`*ORU`** возвращает номер и поле обычного формата, но строка текста
   остаётся как в широком формате (так в оригинале).
5. **Поле `*MCS`** задаётся сразу, если строка ещё пуста, и не сбрасывается
   при смене формата; номер страницы `*NN` снимается с пустой текущей
   страницы сразу.
6. **Рамка и номер страницы** - свои флаги у полноширинных страниц
   (широкий формат, формат А) и у половин обычного листа; рамка на
   краю страницы не рисуется, если поле страницы накрывает этот край
   (текст затирает стойку рамки).
7. **Команды `*STA`/`*STO`/`*STN`** оставляют после себя лишний пробел -
   следующая карта отделяется двумя пробелами.
8. **`*0RU` на первой карте блока** дописывает текущий лист и начинает
   широкий формат со следующей страницы (строка текста - прежняя).
9. **Нумерация страниц сквозная по всем блокам задания**: после
   напечатанного листа номер не используется повторно (в `newfmt` номер
   свежего листа подменялся номером напечатанного - каждый блок начинался
   с «- 1 -»).  Эталон `red-multiblock` (три блока - страницы 1, 2, 3).
10. **`*ST` с числами после пробела** (колонки без линеек парами
   начало-конец, SIPROD.md 4.9) разобран `tabledef` вместо ошибки 10;
   титульный лист записки (`*ST 25 45  46 66`) печатается.  Эталон
   `red-stspace`.
11. **Маркер ячейки ` k)` в середине карты** переключает колонку (текст до
   маркера - в текущую ячейку); прежде « 2)» печатался как текст.  Эталон
   `red-cellmark` (титульная пара «РУКОВОДИТЕЛЬ РАБОТЫ 2)ИСПОЛНИТЕЛЬ»).

Эталонов редактора стало 19: добавлены `red-multiblock`, `red-stspace`,
`red-cellmark` (эталоны сняты с живого оригинала `run.sh`).

## Исправления 07.11.2026 (сверка с оригиналом СИПРОДа)

Оригинальный СИПРОД запускается в эмуляторе (`tests/siprod/run.sh`),
поэтому поведение редактора сверялось с ним на живом оригинале, а не
только по эталонам.  Исправлено в `../source/redakt.pas`:

1. **Не компилировался**: идентификаторы `предолж`/`предорн` были
   набраны смешанной латиницей и кириллицей (`rownоl` с кириллическими
   «о» и «л») - компилятор видел другое имя и выдавал «ИДЕНТИФИКАТОР
   НЕ ОПРЕДЕЛЕН» (5 ошибок).
2. **Линейки таблиц** (`*SL`): вертикаль на стыке рисуется, если она
   есть в завершённой строке или в предыдущей (у ячейки `*NR` убирает
   правую линию, `*NL` - левую); где вертикали нет - горизонт
   прерывается; текст ячейки в таблице с линейками отступается от
   вертикали, в таблице без линеек (`*ST`) - начинается с колонки.
   Эталон `red-table` совпадает побайтно.
3. **Выравнивание**: лишние пробелы распределяются как в оригинале -
   поровну во все промежутки и остаток в последние; единственный
   лишний пробел оригинал ставит во второй с конца промежуток.
4. **Пробелы в тексте сохраняются** (очередь слов помнит число пробелов
   перед словом), граница карты - один пробел, хвостовые пробелы карты
   отбрасываются (в позиционном режиме они сдвигали позицию набора и
   «теряли» следующую карту - `red-position`).
5. **`*` перед пробелом** опускается, как в оригинале; несколько пробелов
   подряд не сливаются (`red-literal`).
6. **Разрядка `*nRC`** добавляет пробелы после каждой литеры, в том
   числе после пробела; пробелов в промежутке больше не удваивается.
7. **Повтор группы** (`*n(текст)`) идёт без разделителя, тело макроса
   вставляется как есть; при вложенном макросе оригинал теряет
   продолжение карты - воспроизведено (`red-group`, `red-macro`).
8. **Позиционный режим** (`*nG`, `*nC`, `*Knc`, `*nF`, `*nRF`): позиция
   набора не сбивается хвостовыми пробелами карты (`red-position`).
9. **Поле `*nMCS`** действует со следующей строки (строка, на которой
   команда встретилась, набирается по старому полю); смена поля не
   выводит пустую строку (`red-margins`).
10. **Абзац `*nS`** не выводит пустую строку, если текущая строка
    пуста; **листинг `*MF`** выводит накопленный текст перед собой
    отдельной строкой, конец листинга (`///`) даёт пустую строку
    (`red-listing`).
11. **Интервал `*nRL`** закрывает текущую строку - новое значение
    действует со следующей (`red-spacing` частично).
12. **Рамка `*RG`** и **номера страниц** (`*nN`, `*NN`) запоминаются на
    странице: `*RG` в середине текста рисует рамку со следующей
    страницы, `*NN` снимает номер со следующих страниц; в формате А
    номер страницы не печатается (`red-frame`, `red-pages`).
